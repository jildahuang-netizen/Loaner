# Loaner complete single-file Apps Script installation

This is an alternative to the multi-file package. Do not mix the two installations.

## Fix ensureFeatures_ is not defined and duplicate declaration errors

1. Back up your current project files and data spreadsheet.
2. In the SAME Apps Script project, keep one script file named Code.gs. Delete the other .gs editor files, including old Features, Registration, Password/Passwords, Contract, Template, and copies. Deleting editor code files does not delete the data spreadsheet. Do not clear Script Properties or SHEET_ID.
3. Replace the entire Code.gs contents with Code.gs from THIS folder. It already contains every server component, including ensureFeatures_, all password functions, and the contract template. Do not paste other .gs files alongside it.
4. Set ADMIN_EMAIL near the top to the same actual Gmail address you already configured. Keep the quotes. Do not change it to the preview address.
5. Keep one HTML file named Index and replace its contents with this Index.html.
6. In Project Settings, show appsscript.json and replace its contents with the supplied manifest. Approve updated scopes if prompted.
7. Save. Do not run registrationCode directly in the editor; it expects an email supplied by the app. Existing installations should not rerun setup or erase spreadsheet properties. New installations run setup once.
8. Deploy → Manage deployments → Edit → New version → Deploy. Open or refresh the /exec URL. Saving editor code alone does not update the deployed version.
9. Try registration or login again. If needed, inspect Apps Script → Executions for the latest error.

## Temporary admin sign-in

Use your configured ADMIN_EMAIL and the password generated by setupTemporaryAdmin. Preview credentials sysadmin@loaner.local / LoanerTemp!2026 do not work in the live app. If you already established a permanent password, use that or the Set or reset password flow.

This package contains the same current functionality as the multi-file edition: registration with email verification and password, admin account approval and email confirmation, requirements review, loan approvals, private document uploads, contracts, amortization, and temporary admin first-password change. It preserves existing spreadsheet records and stored password hashes. The source files in the project change; the existing spreadsheet is reused.

The project owner must apply and deploy this update in their Google account. No live deployment was changed from the authoring environment. Local checks confirm that ensureFeatures_ and its required functions are present and the combined server parses without duplicate top-level declarations. Live Google permissions, email delivery, and storage still require verification in your project.
